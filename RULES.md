# Правила проекта

Документ для единых соглашений команды: структура, стиль, паттерны, процессы.

## 1) Структура проекта

```
src/
	components/
		UI-компоненты и экраны
	lib/
		инфраструктура, интеграции, сторонние SDK-обертки
	utils/
		утилиты без побочных эффектов
	types/
		общие типы/алиасы
	assets/
```

### 1.1 Именование

- Компоненты: `PascalCase` (например, `MatchmakingBar`).
- Хуки: `useXxx`.
- Утилиты: `camelCase` (например, `formatTime`).
- Типы: `PascalCase` (например, `Stage`).
- Файлы компонентов: `PascalCase.tsx`.
- Файлы утилит/типов: `kebab-case.ts` или `camelCase.ts` — сохраняйте текущий стиль папки.

## 2) Компонентный подход

- `App.tsx` — только композиция. Логика и UI дробятся на компоненты.
- Один компонент — один файл.
- Компонент не должен знать о внешнем состоянии без явных пропов.
- Выносите повторяющиеся блоки в `components/`.

## 3) Логика и состояние

- Эффекты и таймеры — максимально локально или в хук.
- Глобальные состояния — только если есть общая потребность.
- Избегайте лишних `useEffect`, объединяйте связанные эффекты.

## 4) Типизация

- Не использовать `any`.
- При пробелах в типах сторонней библиотеки допускается `as unknown as` локально.
- Экспортируйте общие типы в `src/types`.

## 5) Стили и CSS

- Классы в `className` — без дублирования.
- Повторяющиеся наборы классов — выносить в компонент.
- Избегать инлайновых стилей, если можно.

## 6) Анимации

- Все анимации должны быть изолированы в компонент.
- Никакой анимационной логики в `App.tsx`.
- Для сложных анимаций используйте специализированный компонент.

## 7) Аудио и медиа

- Звуки — только через единый слой (обертку/утилиту), не встраивать в несколько компонентов.
- Любая инициализация медиа — в `useEffect` с корректным cleanup.

## 8) Производительность

- Мемоизация (`useMemo`, `useCallback`) только при реальной необходимости.
- Удаляйте таймеры/RAF в cleanup.
- Не создавайте новые объекты/функции в JSX без нужды.

## 9) Ошибки и устойчивость

- Все таймеры/RAF/обработчики событий — с удалением.
- Любые `setTimeout`/`setInterval` хранить в `useRef`.
- Учитывайте размонтирование компонента.

## 10) Процесс изменения кода

- Перед коммитом: читаемость, минимальные диффы, без лишних форматирований.
- Если добавлен компонент — добавьте пропсы/типы/описание по месту.
- Переиспользуйте существующие компоненты/утилиты.

## 11) Паттерны

- **Presentational / Container**:
	- Presentational — только UI.
	- Container — состояние/эффекты.
- **Single Responsibility**:
	- компонент делает одну вещь и делает её хорошо.
- **Clean-up first**:
	- любой побочный эффект обязан иметь очистку.

## 12) Документация

- Если меняется поведение/структура — обновляйте этот файл.
- Публичные функции/компоненты — краткий комментарий при необходимости.
